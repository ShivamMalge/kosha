kosha gate — planning-time library check.

NEVER fire if any of these hold:
- implementation of this component already begun this session
- under roughly 30 lines
- glue, wiring, config plumbing, type shuffling between existing things
- rename, reorder, extract, docstring, typo fix
- project-specific business rules
- the project already depends on a library for this domain

Otherwise FIRE only if at least two of three hold:
1. the component would take roughly 80+ lines of non-trivial logic. Judge by what the component must do, not by how much detail the request gives — a terse request and a detailed one can describe the same component.
2. a recognized problem class — retry, backoff, rate limiting, parsing,
   serialization, validation, scheduling, concurrency primitives, protocol,
   format handling, caching, diffing
3. would warrant its own test file

Genuinely borderline → do not fire.

Emit exactly one line:
  KOSHA: FIRE <domain>
  KOSHA: DECLINE <clause>

On FIRE only, read SKILL.md in the kosha skill dir and follow it.
On DECLINE, continue normally.
